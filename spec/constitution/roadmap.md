6. **005 · Contact Section** — Complete: `id="contact"` section (`src/components/Contact/`) with contact links from `src/data/contact.ts` (`CONTACT`, also read by the terminal) and a contact form (name, email, message) posted to `POST /api/contact` (`src/app/api/contact/route.ts`), which emails JuanMa594 as plain text via Resend with `reply_to` set to the visitor. The route checks the request origin (`SITE_URL`, plus localhost in dev), rate-limits to 3 submissions per IP per 10 minutes (in-memory, best effort), caps and validates the body with the validation shared with the client (`src/lib/contactValidation.ts`), ignores honeypot submissions and returns only generic errors. Also: a reusable `DownloadCvButton` (Hero, Experience & Education, Contact; file `public/cv/JuanMa-CV.pdf`, hidden when `CV_PATH` is null), a "Contact" Header item (the URL hash sync follows it), a `/contact` terminal command (replaces `/socials`) and a toast for form feedback. One new dependency: `resend`. Env vars (`RESEND_API_KEY`, `CONTACT_TO_EMAIL`, `CONTACT_FROM_EMAIL`, `SITE_URL`) are documented in `README.md` and `.env.example`; they must also be set in Vercel. Known limits: rate limit resets per serverless instance; free Resend sender (`onboarding@resend.dev`) only delivers to the Resend account's own address. Visual checks (dark/light, mobile/desktop, `#contact` hash at the bottom) still pending in `features/005-Contact/tasks.md`.
